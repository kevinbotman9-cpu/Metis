# METIS engine — Kotlin

A second implementation of the decision engine, held to the TypeScript
reference's output by two committed corpora.

## Why this exists

The platform's central claim is that a decision replays byte-identically. That
rests on a chain hash, which rests on a serialisation and on the engine's own
semantics. While there was one implementation, "the semantics" meant one
directory of TypeScript, and the claim was really about that code rather than
about a specification.

This module makes the difference visible. It implements
[ADR-003](../../docs/adr/ADR-003-canonical-serialisation.md) and the engine on
top of it, in another language, and is checked against output generated by the
reference. Nothing here defines anything — it can only agree or disagree.

## Run it

```bash
./gradlew test
```

Reads both corpora from the repository root, so run it from this directory. If
either is missing, run `npm run corpus` at the root first.

| Suite | Cases | What it proves |
|---|---|---|
| `ConformanceTest` | 67 | The two agree on how to serialise and hash a value |
| `DecisionConformanceTest` | 22 | The two agree on what a decision *is* — same eliminations, scores, winner, chain hash |

The second exists because the first is necessary and not sufficient. Two
engines can hash identically and still disagree about which offer won.

## What it deliberately does not do

**No JSON library in `main`.** A canonicaliser built on Jackson or kotlinx would
inherit that library's opinions about number formatting, key ordering and
surrogate handling — the three things ADR-003 exists to pin down. `main` depends
on nothing beyond the JDK; Jackson appears only in tests, to read the corpora.

**No `Double.toString`.** ECMAScript's `Number::toString` and Java's disagree,
and not cosmetically: `1` vs `1.0`, `1e+21` vs `1.0E21`. On JDK 17
`Double.toString` is also not shortest-round-trip, so `5e-324` comes back as
`4.9E-324`. Substituting it fails 25 of the 58 serialising cases.

**No `Math.pow`.** `StrictMath.pow` is fdlibm by specification, and so is V8's
`Math.pow`; `java.lang.Math.pow` is permitted to differ by an ulp, which after
rounding to 8dp can change a hash. Being straight about the evidence: the corpus
does not currently distinguish them, and the rule stands anyway — see ADR-003
§4a for why.

**No timings.** They are the measured half of a trace, excluded from the hash by
design. A port that invented them would be adding a field with nothing to
compare against.

**Catalogue and input hashes are computed from the raw JSON tree**, not from the
typed model. The typed model omits fields the engine never reads — display
names, audit timestamps — and rebuilding the exact key set from it would make a
hash depend on how faithfully the port modelled metadata it does not use. It
also doubles as a decoder check: if Jackson read a number differently from V8,
the catalogue hash fails before anything else can go wrong.

## What is not ported

Integration resolution (`resolveInputs`), replay, and the compiler. Resolution
is I/O and sits outside the deterministic core by design, so it is not part of
what has to agree byte for byte. Replay is `execute` plus a hash comparison, so
porting it adds nothing the corpus is not already proving.
